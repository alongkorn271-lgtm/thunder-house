# งานต่อยอดจากโมเดลก่อสร้าง (deliverables)

โมเดลก่อสร้างจาก Workflow B คือแหล่งความจริงเดียว — ทุกผัง รูปตัด ตารางปริมาณ หน้าเว็บ และตัวเลขต่อรอง
ถอดจากรูปทรงในโมเดล ไม่วาดเส้นเอง และไม่พิมพ์ตัวเลขเองถ้าอ่านจาก report ได้ เพื่อให้ทุกชิ้นตรงกันเสมอ
เมื่อแก้โมเดลแล้ว build ใหม่ ทุกอย่างสร้างใหม่ได้ด้วยสคริปต์ชุดเดิม

ก่อนเริ่ม ให้มีสิ่งเหล่านี้ (ถ้ายังไม่มี ให้ทำ Workflow B ของ `nuea-ai-blender-house` ให้จบก่อน):
- `Construction/<PROJ>_Construction.blend` ที่ build จาก Blender ว่างแล้วผ่าน selfcheck (problems: 0)
- log ของการ build (`build_kk01.py` พิมพ์ report ทุกขั้น) — เก็บเป็น `build_report.log`
- loader ของโปรเจกต์ (`scripts/kk01_load.py`) ที่มี `_world_bm`, `_obj_boxes`, `_world_bars`, ชื่อ collection `C_*`

ตอบผู้ใช้เป็นภาษาไทย ข้อมูลในหน้า/แบบเป็นภาษาไทย ชื่อแบบมีภาษาอังกฤษกำกับ (`ผังฐานราก  FOOTING PLAN`)

## สคริปต์ใน skill นี้

คัดลอกไปไว้ในโปรเจกต์ก่อนแก้ (อย่าแก้ในโฟลเดอร์ skill) — ทุกไฟล์เป็นตัวที่ใช้ได้จริงกับ KK01 บ้านเกาะคา
ส่วนที่ต้องเปลี่ยนต่อโปรเจกต์ดูที่ `references/project_config.md`

| ไฟล์ | ทำอะไร |
|---|---|
| `scripts/blender/export_model_json.py` | ส่งออกรูปทรงทุกชั้นงานเป็น `model.json` (กล่อง / สามเหลี่ยม / เส้นโค้ง, มม.) |
| `scripts/blender/render_sheets.py` | ภาพ render นำเสนอ EEVEE + Freestyle: ขั้นปัจจุบันสีเด่น ขั้นก่อนหน้าสีขาว, ภาพเหล็กเสริมคอนกรีตโปร่ง, ภาพแยกชิ้น, รายละเอียดแต่ละขั้น |
| `scripts/viewer/template.html` + `build_site.py` | หน้าเว็บ 3D (three.js r128) + แท็บ ชั้นงาน/ชิ้นส่วน/ปริมาณ/เทียบ BOQ/ต่อรอง/ต้องยืนยัน/ภาพ render |
| `scripts/viewer/make_offline.py` | HTML ไฟล์เดียว ฝังภาพแล้ว: ฉบับเต็ม + ฉบับส่งต่อ (ตัดแท็บต่อรอง) |
| `scripts/boq/boq_parse.py` | อ่าน BOQ PDF ผรม. เป็นแถว + ตรวจ จำนวน × ราคา = จำนวนเงิน ทุกบรรทัด |
| `scripts/boq/make_xlsx.py` + `recalc_excel.ps1` | Excel 5 แผ่น (สรุป / อัตราเผื่อ / ต่อรอง / เทียบรายบรรทัด / รายการขาด) สูตรจริง คำนวณใหม่ใน Excel |
| `scripts/drawings/make_sheets.py` + `sheets_late.py` | ชุดแบบ A3 ST-00…ST-18 (ใช้ `lib/dwg_lib.py` จาก shop-drawing-3d + ฟอนต์ IBM Plex Sans Thai) |
| `scripts/drawings/render_pdf.py` | HTML → PDF A3 + PNG ตรวจแบบด้วย Chrome headless แล้วบีบอัด PDF (68 MB → 4 MB) |

## ลำดับงาน

ทำตามที่ผู้ใช้ขอ ไม่จำเป็นต้องทำครบทุกส่วน แต่ส่วนที่ 1 (ส่งออกข้อมูล) ต้องมาก่อนเสมอ

### 1. ส่งออกข้อมูลจากโมเดล
```bash
OUT=data/model.json blender -b Construction/<PROJ>_Construction.blend --python-exit-code 1 -P scripts/export_model_json.py
```
ตรวจจำนวนชิ้นต่อชั้นที่พิมพ์ออกมา ถ้าชั้นไหนหายไป (เช่น หลังคาไม่มีกระเบื้อง) มักเป็นเพราะ `SKIP_EL` ตัด element นั้นทิ้ง
— `tile_bed` ใน ST08 คือกระเบื้องหลังคา ไม่ใช่ปูนรองกระเบื้อง

### 2. ภาพ render นำเสนอ
`blender -b <blend> -P render_sheets.py -- <out_dir> [ชื่อ shot ...]` (ไม่ save .blend) — ทดสอบ 1 shot ก่อน (~25 วินาที) แล้วค่อยสั่งทั้งชุดเบื้องหลัง
- ลุคที่ผู้ใช้ชอบ: isometric ortho จากหน้า-ซ้าย, คอนกรีตของขั้นปัจจุบันเป็นสีประจำขั้น (ST01 ฟ้า, ST02 เขียว, ST03 ม่วง, ST04 ทราย, ST05 ส้มอิฐ, ST06 น้ำเงิน), ขั้นก่อนหน้าขาว, เส้นขอบ Freestyle, เงาจากดวงอาทิตย์
- ภาพเหล็กเสริม: คอนกรีตโปร่ง alpha ~0.07 + เหล็กสีสนิมเข้ม + ขยายความหนาเส้นเหล็ก ×1.7 ไม่งั้นภาพจะมัวทั้งภาพ
- **ปิด Freestyle (`lines=False`) ทุก shot ที่มีกระเบื้อง สี หรือบ้านทั้งหลัง** — Freestyle บนกระเบื้องหลายหมื่นแผ่นกินแรม 17 GB และค้าง
- วัสดุที่เป็น texture (กระเบื้อง CPAC) ไม่ขึ้นใน EEVEE แบบนี้ → override สีทึบ (เทาเข้ม)
- อย่า `taskkill /IM blender.exe` แบบเหมา — จะปิด Blender ที่ผู้ใช้เปิดอยู่ด้วย ให้ใช้ TaskStop ของงานเบื้องหลัง

### 3. หน้าเว็บ 3D (artifact)
ถ้าผู้ใช้มี artifact ต้นแบบ (เช่น "LiDAR Lab Station 3×6 ม.") ให้อ่านด้วย Artifact `read` ก่อนแล้วทำตามโครงของมัน
- `build_site.py <build_report.log>` รวม `template.html` + `model.json` + report → `index.html` (ข้อมูลฝังในไฟล์ ~2 MB)
- ใน `template.html` แก้ array `BOQ`, `NEG`, `ISSUES`, `WASTE` ตามโปรเจกต์ (ค่าโมเดลจาก report เท่านั้น)
- ทดสอบด้วย `python -m http.server` + browser pane: desktop, mobile 375 px (ห้ามล้นแนวนอน: `.app{grid-template-columns:minmax(0,1fr)}`), dark mode
- publish ด้วย Artifact tool พร้อม `files` ของภาพ (path แบบเต็ม `C:\Users\<name>\...` ไม่ใช่ `ALONGK~1`)
- แชร์ลิงก์ artifact ออกนอกองค์กรอาจทำไม่ได้ (สิทธิ์บัญชี) → `make_offline.py <out_dir>` ได้ HTML ไฟล์เดียว 2 ฉบับ
  ส่งทางไลน์ได้ แต่ iPhone มักเปิดเป็นพรีวิวที่ไม่รัน 3D — บอกผู้ใช้ตรง ๆ และเสนอโฮสต์เป็นลิงก์หรือ PDF สรุปแทน

### 4. เทียบ BOQ ผู้รับเหมา + ต่อรอง + Excel
อ่าน `references/boq_negotiation.md` ก่อนทำ — มีวิธีคิดที่ผู้ใช้กำหนดไว้แล้ว สรุปสั้น:
- **ฝั่งเรา = ปริมาณจริงจากโมเดล (+ เผื่อตามอัตรามาตรฐาน)** · **ฝั่ง ผรม. = ตามใบของเขาทุกบรรทัด** ไม่ใช้ BOQ เก่าของเรามาปน
- `boq_parse.py <pdf> rows.txt` → ตรวจผลคูณ/ผลรวมทุกหมวด (เช่น จำนวน × ราคาไม่เท่ากับจำนวนเงินที่เขียนในใบ)
- มูลค่าทุกจุด = ส่วนต่างปริมาณ × **ราคาต่อหน่วยของ ผรม. เอง** (ค่าของ + ค่าแรง) — อธิบายให้ผู้ใช้เห็นที่มาของราคา เช่น คอนกรีต = ค่าของ/ลบ.ม. + ค่าแรง/ลบ.ม.
- แบ่ง 4 กลุ่ม: ต้องได้ตามแบบ (ไม่ใช่ของแถม) / รายการที่ใบยังไม่มี / ปริมาณที่เผื่อเกิน / ของที่ขอเพิ่มแลก
- Excel: `make_xlsx.py <template.html> <out.xlsx>` แล้วคำนวณสูตรใหม่ (Windows ไม่มี LibreOffice → ใช้ `recalc_excel.ps1` ผ่าน Excel COM) ตรวจ error = 0 และอ่านค่ากลับมาเทียบกับหน้าเว็บ
- ชื่อลูกค้าในใบเสนอราคาเป็นข้อมูลส่วนตัว ไม่ต้องใส่ในหน้าเว็บ/แบบ; แท็บต่อรองเป็นกลยุทธ์ของผู้ใช้ — เตือนว่าอย่าส่งฉบับเต็มให้ ผรม.

### 5. ชุดแบบก่อสร้าง A3 ตามขั้นงาน
อ่าน `references/drawing_sheets.md` ก่อนจัดแผ่น — มีผังพื้นที่ของแผ่น บทเรียนเรื่องตำแหน่ง และวิธีเลือกระนาบตัด
- รูปแบบของเราเอง (ไม่ลอกหัวกระดาษ โลโก้ หรือชื่อวิศวกรจากแบบตัวอย่างของบริษัทอื่น) เรียงตามขั้นงาน 1 แผ่นต่อ 1 ขั้น:
  กล่องข้อมูลขั้นงาน + ผัง 1:125 + ตารางปริมาณจาก report (ซ้าย) · ภาพ render ใหญ่ + ภาพรายละเอียด + รูปตัด/รูปด้าน/ตาราง (ขวา)
- `python make_sheets.py` → `python render_pdf.py [ST-xx ...]` → เปิดดู PNG ทุกแผ่น แก้ซ้อน/ล้น 2–3 รอบ
- ตรวจ PDF: จำนวนหน้า, A3 420×297, ฟอนต์ IBM Plex Sans Thai ฝังแล้ว (`fitz` get_fonts)
- คงสถานะ DRAFT ช่องลงนามว่าง — งานโครงสร้างต้องให้วิศวกรโยธาตรวจและลงนาม

## บทเรียนจากงานจริง (ทุกส่วน)
- เขียน patch ที่มี `\n`, quote ซ้อน, หรือ backslash ด้วย Write tool เป็นไฟล์ .py แล้วรัน — heredoc ใน bash พังบ่อย
- Python บน Windows: ตั้ง `PYTHONIOENCODING=utf-8` ก่อนพิมพ์ภาษาไทย (ไม่งั้น UnicodeEncodeError cp1252); `python -I` ไม่อ่านตัวแปรนี้ ให้เขียนลงไฟล์แทน
- path ใน scratchpad: ใช้ `C:/Users/ALONGK~1/...` ได้ใน bash แต่ Artifact `files` ต้องใช้ path ยาว
- ภาพที่ผู้ใช้แนบในแชตมักมีไฟล์ต้นฉบับใน root ของโปรเจกต์อยู่แล้ว — หาให้เจอก่อนคัดลอกซ้ำ
- ผู้ใช้ให้ใช้ค่า recommend เมื่อมีเรื่องแปลก แล้วจดค่าที่สมมติไว้ให้เห็น (ในหน้า/แบบ/spec)
